# Campaign ↔ EverRoom context

## Context

A campaign is the technical/work boundary. An EverRoom Room is the evidence/knowledge boundary. Do not mirror either database into the other. The Gateway client lives in `src/metagit/core/integrations/everroom/` and must stay isolated from campaign orchestration.

## Steps

1. Persist only `room_id` + `endpoint` on `CampaignDocument.context.providers[]`. Tokens stay in `METAGIT_EVERROOM_TOKEN` / local AppConfig.
2. Assemble context on demand via `CampaignContextService.resolve` (`context_schema_version: "1"`). Keep `campaign` / `metagit` / `everroom` slices separate with `source` provenance.
3. Read-only `campaign context` degrades to MetaGit-only when the Gateway is down; `attach`/`sync` fail instead.
4. Map repos by Git remote identity (`github.com/org/repo`), never filesystem paths. Unmapped stays `unmapped`.
5. Sync writes a generated document titled `Campaign Context (generated by MetaGit)` and must not overwrite human-authored Room documents.
